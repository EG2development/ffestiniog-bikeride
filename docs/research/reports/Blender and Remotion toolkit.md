# Fix the grid, then add lean tools

The most valuable addition to this pipeline is not a package. It is one open-licence grid file: on this machine pyproj 3.8 cannot find the OSTN15 transformation grid and silently falls back to a Helmert transform rated at **2.0 m accuracy**, enough to shift OSM roads off a 1 m lidar cut. After that, the shortlist is small and almost entirely free. On the data side, add **pydelatin** (error-bounded terrain meshes), **scikit-image** (SSIM scoring for photo matches), **fake-bpy-module-5.2** (type stubs) and a skyline-against-DSM camera solver built on the NumPy, SciPy and OpenCV you already have. Inside Blender, use the **5.2 LTS Geometry Nodes** for rails, roads and walls, **MTree** for trees, **ambientCG** next to Poly Haven, the built-in **multiple-scattering Sky Texture**, and **CMU / Quaternius** motion for walkers. In Remotion, add **seven official 4.0.539 packages** led by `@remotion/media` and `@remotion/fonts`. Most popular alternatives fail this project for one of three reasons: their licences break the open-provenance rule (Google 3D Tiles, Megascans, Mixamo, DUSt3R/MASt3R, Bandai Namco), they have no Blender 5 build (Building Tools, Buildify, Archimesh, fSpy importer), or they cannot work from scattered single Commons photos (COLMAP, Meshroom, Gaussian splatting). Total spend for the "add now" tier is zero. The paid options worth budgeting later are The Grove 2.3 (from about €89) and Physical Atmosphere² ($118, beta).

## A missing OSTN15 grid costs two metres of alignment

A local check on the project machine showed pyproj 3.8.0 (PROJ 9.8.1) reporting `network False` and `best_available False`. Because `uk_os_OSTN15_NTv2_OSGBtoETRS.tif` is missing, it chooses "OSGB36 to WGS 84 (6)" with a stated **2.0 m** accuracy instead of the OSTN15 operation ([epsg.io 27700-to-4326](https://epsg.io/27700-to-4326)). The grid is published openly at `cdn.proj.org`. There are three ways to fix it. You can call `pyproj.network.set_network_enabled(True)`, you can set `PROJ_NETWORK=ON`, or, more reproducibly, you can download the file once into `pyproj.datadir.get_user_data_dir()` (or run `projsync --file uk_os_OSTN15_NTv2_OSGBtoETRS.tif`) and add a test that asserts `TransformerGroup(...).best_available`. rasterio bundles its own GDAL 3.12.2 and PROJ data directory, which probably needs the same file, so check that before trusting it. pyproj itself is current: 3.8.0, MIT, Python ≥3.12, with a Windows cp312 wheel ([PyPI pyproj](https://pypi.org/project/pyproj/)).

As briefed, this affects only new pyproj-based code, because `scripts/dem/bng.py` uses its own Helmert transform under ADR 8. There is a second-order risk, though. Once some new code reprojects with OSTN15 while `bng.py` keeps its Helmert parameters, the two can disagree by up to the Helmert error in the same scene. Pick one transform per coordinate path and record the choice and the PROJ version in the source register.

The other cheap wins are about pipeline hygiene. The local 5.2.4 RC `blender --help` confirms `--python-exit-code <n>`. Without it, a headless script that raises an exception can still exit 0 and fool both CI and Claude Code. The recommended invocation is `blender -b --factory-startup --offline-mode -q --python-exit-code 1 -P script.py -- args`. Pin add-ons explicitly, because `blender -c help` showed that user extensions such as MPFB load even in command mode. For editors and static checks, `fake-bpy-module-5.2` (MIT, released almost daily through October 2026) gives pyright or mypy 5.2-accurate stubs for `scripts/blender/*.py` without starting Blender ([PyPI fake-bpy-module](https://pypi.org/project/fake-bpy-module/)). On the MCP side, the community `mcp-for-blender` server is MIT-licensed, but its socket "has no authentication or encryption" and it collects anonymous usage by default unless `DISABLE_TELEMETRY=true` is set ([GitHub ahujasid/blender-mcp](https://github.com/ahujasid/blender-mcp)). Pin it as `uvx mcp-for-blender==X.Y.Z`, put `DISABLE_TELEMETRY=true` in the server's env block, and start the add-on server only while it is needed. The official Blender Lab MCP extension (v1.0.3, Blender 5.1+) also listens on port 9876 and speaks a different protocol, so never enable both at once ([blender.org/lab/mcp-server](https://www.blender.org/lab/mcp-server/)).

## Terrain and photo matching need four libraries, not a photogrammetry suite

rasterio 1.5.2 already covers windowed COG reads of the Welsh DTM and DSM ([PyPI rasterio](https://pypi.org/project/rasterio/)). The real gap is meshing. **pydelatin 0.4.0** (MIT, Windows cp312 wheel, released 9 October 2026) builds a triangulated irregular network (TIN) that stops refining once a maximum vertical error is met. You can therefore produce an LOD chain straight from 1 m DTM tiles, for example at 0.25 m, 1 m and 4 m error, which is far lighter on a 6 GB card than displacing a dense grid ([PyPI pydelatin](https://pypi.org/project/pydelatin/)). pymartini 0.6.0 is the faster alternative, but it needs (2^n+1)² tiles ([PyPI pymartini](https://pypi.org/project/pymartini/)). The older heremaps/tin-terrain is archived ([GitHub heremaps/tin-terrain](https://github.com/heremaps/tin-terrain)). A canopy height model needs no new tool: DSM minus DTM is a NumPy subtraction on two rasterio arrays. **xdem 0.2.3** (Apache-2.0) becomes worth adding only if DSM and DTM tiles turn out to be misregistered ([PyPI xdem](https://pypi.org/project/xdem/)).

For raw point clouds (bridges, quarry faces, building footprints the 2.5D raster misses), `pip install "laspy[lazrs]"` reads LAZ on Windows with no compiler. laspy 2.7.0 is BSD-2 and lazrs 0.8.2 is MIT ([PyPI laspy](https://pypi.org/project/laspy/); [PyPI lazrs](https://pypi.org/project/lazrs/)). PDAL and the PyPI `gdal` package have no Windows wheels, so they would mean adopting conda-forge or OSGeo4W, which is not justified here ([PyPI pdal](https://pypi.org/project/pdal/)). **whitebox-workflows 2.0.6** is now licensed "MIT OR Apache-2.0" with a cp312 wheel, a reversal of the 1.x line, which "is not free". The rewrite is still in a "soft launch", so treat it as a later option for ground filtering and terrain derivatives ([PyPI whitebox-workflows](https://pypi.org/project/whitebox-workflows/); [OSGeo-Discuss, June 2026](https://lists.osgeo.org/pipermail/discuss/2026-June/040372.html)).

On the vector side, the own OSM fetcher can stay. If live Overpass results prove hard to reproduce, a dated Geofabrik Wales PBF read with **osmium 4.3.2** (BSD-2, cp312 wheel) gives a fixed snapshot to register ([PyPI osmium](https://pypi.org/project/osmium/)). pyrosm 0.28 also reads PBFs, but it went from 0.25 to 0.28 in one October week, so pin it hard if you use it ([PyPI pyrosm](https://pypi.org/project/pyrosm/)). Overture buildings add nothing: their heights come mainly from USGS lidar, and no evidence of Welsh coverage turned up ([Overture buildings guide](https://docs.overturemaps.org/guides/buildings)). Sampling DSM minus DTM inside OSM or OS footprints gives better heights. Mind the Python floor as well. momepy 1.0 and pyproj 3.8 now require Python ≥3.12, and rioxarray 0.24 requires ≥3.13, so pin `rioxarray<0.24` on the system Python 3.12 ([PyPI rioxarray](https://pypi.org/project/rioxarray/)).

Photo matching is where the research changes the plan most. Multi-view reconstruction needs dozens of overlapping views of one subject, and the project's Commons photos are scattered single frames. COLMAP, OpenMVS (AGPL-3.0), Meshroom and Gaussian-splat training therefore cannot do the job ([GitHub cdcseacave/openMVS](https://github.com/cdcseacave/openMVS)). The established alternative registers each photo against the terrain itself. Starting from the geotag and an approximate field of view, you match the photo's horizon silhouette to a horizon rendered from the DEM, then refine with 2D–3D correspondences ([Produit et al., ISPRS Annals 2014](https://isprs-annals.copernicus.org/articles/II-3/127/2014/isprsannals-II-3-127-2014.pdf); [Baboud et al.](https://resources.mpi-inf.mpg.de/photo-to-terrain/photo-to-terrain.pdf)). No maintained package does this, so it is custom code. It needs nothing new: render a skyline from the DSM, extract the photo's skyline with OpenCV, and fit yaw, pitch, roll and focal length with `scipy.optimize`. Today `scripts/blender/photo_match.py` only composes side-by-side comparisons, so this solver is the natural next step. To score a match, add **scikit-image 0.26.0** (BSD, cp312 wheel) and compute SSIM on edge or gradient maps rather than raw RGB, alongside OpenCV ECC alignment and a Chamfer distance on Canny edges ([PyPI scikit-image](https://pypi.org/project/scikit-image/)). **pycolmap 4.2.1** (BSD-3, cp312 wheel) is the upgrade path once you have hand-picked tie points and want bundle adjustment beyond OpenCV's `solvePnP` ([PyPI pycolmap](https://pypi.org/project/pycolmap/)).

The learned shortcuts fail on licence and memory. DUSt3R and MASt3R code and checkpoints are **CC BY-NC-SA 4.0** ([GitHub naver/mast3r](https://github.com/naver/mast3r)). Only the gated VGGT-1B-Commercial checkpoint permits commercial use ([HF facebook/VGGT-1B-Commercial](https://huggingface.co/facebook/VGGT-1B-Commercial)). Even the newer VGGT-Omega-1B peaks at **about 6.0 GB for a single frame** on an A100, which leaves no headroom on a 6 GB RTX 2060 ([GitHub facebookresearch/vggt-omega](https://github.com/facebookresearch/vggt-omega)).

## Inside Blender 5.2, built-in nodes beat most add-ons

Blender 5.2 LTS (supported until July 2028) shipped Geometry Nodes features that make in-house generators cheap to write: Lists, Geometry Bundles, string fields with Split String for OSM tag parsing, a Mesh Bevel node, Transfer Attributes, and node-tool inputs settable from Python ([5.2 GN notes](https://developer.blender.org/docs/release_notes/5.2/geometry_nodes/)). Blender 5.0 had already added SDF grids with Boolean, Offset and Fillet nodes, which can blend a trackbed or road formation into the lidar terrain if voxels stay at 0.5 m or coarser ([5.0 GN notes](https://developer.blender.org/docs/release_notes/5.0/geometry_nodes/)). No third-party kit beats this. Building Tools stops at Blender 4.0, Buildify dates from 3.2, Archimesh's Blender 5 patch is unmerged, and the free road and rail node files carry "royalty-free" or unstated licences ([Building Tools](https://github.com/ranjian0/building_tools); [Archimesh PR #5](https://projects.blender.org/extensions/archimesh/pulls/5); [Superhive road generator](https://superhivemarket.com/products/procedural-road-generator-geometry-nodes)). A former standard-gauge formation is a Curve to Mesh sweep plus sleepers instanced on resampled points, about a dozen nodes driven from Python. Two compatibility traps matter for existing tests. First, Blender 5.0 changed Random Value seeds, and 5.2 changed the Compare and Random Value socket identifiers and the GN modifier-property API ([Blender 5.2 release notes](https://developer.blender.org/docs/release_notes/5.2/)). Second, scatter snapshots tuned on 4.x need re-baselining.

Vegetation is the biggest asset gap. No free, CC0, Blender-5-verified library of sessile oak, birch, rowan, Sitka spruce, gorse, bracken or heather turned up. **MTree** is the free route: GPL code on extensions.blender.org, with official Blender 5.1 support listed. Its generated meshes belong to you and can be registered as project-original ([extensions.blender.org: modular-tree](https://extensions.blender.org/add-ons/modular-tree/)). Bake two or three LODs plus a camera-facing card and scatter them with plain Instance on Points, which suits EEVEE 5.2: its instancing is "up to twice as fast" and it adds 1.5 GB and 2 GB shadow-pool sizes ([5.2 EEVEE notes](https://developer.blender.org/docs/release_notes/5.2/eevee/)). If MTree cannot produce convincing gnarled Atlantic oakwood, **The Grove 2.3** is Blender 5 compatible and was historically priced from €89 (Starter), though that price comes from 2.1-era coverage ([Digital Production](https://digitalproduction.com/2026/03/02/the-grove-2-3/); [renderu](https://renderu.com/en/news/post/25403)). Botaniq's listing showed only Blender 3.3–4.2 support ([Blender Market](https://blendermarket.com/products/botaniq-trees)). SpeedTree needs a $199/year account even for Indie ([Unity: SpeedTree](https://unity.com/kr/products/speedtree)).

For materials, add **ambientCG** beside Poly Haven. It is CC0 and explicitly allows redistribution "even if that means redistributing them as files" ([licenseorg: ambientCG](https://licenseorg.com/guide/3d-assets/ambientcg)). Build slate walls and roofs procedurally over 2K CC0 rock albedo rather than buying 8K slate packs. Megascans stopped being free on 31 December 2024 and now sits under Fab's Standard Licence, which forbids redistribution, while the NoAI tag adds further restrictions ([UE forum](https://forums.unrealengine.com/t/reminder-free-megascans-ends-soon/2203090); [Epic docs](https://dev.epicgames.com/documentation/en-us/fab/licenses-and-pricing-in-fab)). For the sky, Blender 5.0's Sky Texture gained a "Multiple Scattering" model, and a release recap says it works in EEVEE, though the official EEVEE notes do not mention it, so confirm with a test render ([ubunlog](https://en.ubunlog.com/blender-5-0-novedades-renderizado-hdr/)). Pair it with EEVEE volumetric mist and a Poly Haven overcast HDRI.

For people, MPFB stays. The registrable motion sources are the CMU database (about 2,605 sequences, described as free for all uses) and the CC0 Quaternius clips distributed through Mesh2Motion ([roboticscenter.ai: CMU](https://www.roboticscenter.ai/datasets/cmu-mocap/); [GameFromScratch: Mesh2Motion](https://gamefromscratch.com/mesh2motion-open-source-mixamo-alternative/)). CMU has a minor licence-wording conflict, because a Hugging Face derivative is tagged CC-BY-4.0, so record the source you actually downloaded ([HF: CMUMDB](https://huggingface.co/datasets/ckinpdx/CMUMDB)). The cgspeed BVH files are 120 fps with joint flips, so resample and clean them ([cgspeed group](https://groups.google.com/g/bvhacker/c/r906SGjjcTA)). No CC0 cycling rig verified for Blender 5 exists, so the project's own bike script with IK pedal and handlebar targets remains the cleanest route. BlendSwap #13264 is a CC0 bicycle mesh you can use as a reference or replacement ([BlendSwap 13264](https://www.blendswap.com/blend/13264)).

BlenderGIS is the only open, Blender-5-patched GIS add-on with real EPSG handling. Its v2.2.11 to v2.2.15 releases fixed Blender 5 problems. However, its built-in reprojection engine knows only WGS84, Web Mercator and UTM. For EPSG:27700 it falls back to GDAL, pyproj or the online epsg.io service, and the last of these breaks reproducibility ([reproj.py](https://raw.githubusercontent.com/domlysz/BlenderGIS/master/core/proj/reproj.py); [releases](https://github.com/domlysz/BlenderGIS/releases)). The project already imports lidar and OSM itself, so BlenderGIS is only a later cross-check tool, and only with pyproj installed into Blender's Python 3.13 and `proj_engine='PYPROJ'` pinned.

## Remotion needs seven official packages and one handoff rule

The project is on the newest Remotion, 4.0.539 (26 October 2026). `@remotion/three` pins `remotion` exactly, so every added `@remotion/*` package must be pinned to the same version ([npm @remotion/three](https://www.npmjs.com/package/@remotion/three)). Seven are worth adding. **`@remotion/media`** leads: its `<Video>` component is "the recommended component for embedding videos", decodes the exact timeline frame and falls back to `<OffthreadVideo>` ([docs](https://www.remotion.dev/docs/media/video)). **`@remotion/fonts`** (MIT) self-hosts fonts so renders need no network, and **`@remotion/captions`** (MIT) supplies the standard caption type fed by whisper converters ([docs](https://www.remotion.dev/docs/captions/api)). **`@remotion/transitions`** handles cuts between shots; npm lists it as "UNLICENSED", meaning it falls under the Remotion licence. The last three are small helpers: **`@remotion/layout-utils`** fits bilingual title text of different lengths, **`@remotion/noise`** gives deterministic camera shake and organic motion, and **`@remotion/paths`** draws the route line progressively on map overlays.

The Free License covers individuals, non-profits and companies of up to three; larger organisations pay $25 per seat per month ([LICENSE.md](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md); [remotion.pro](https://www.remotion.pro/license)). Welsh ŵ and ŷ sit in Latin Extended-A, so self-host a font with Latin-Ext coverage and render a glyph test card.

The handoff rule is to render Blender as PNG sequences at the Remotion composition fps, so that Blender frame N is frame N of a `<Sequence>`. Encode long opaque shots to an intermediate only to keep Studio responsive. ProRes decoding needs `@mediabunny/prores` from 4.0.487 ([media support](https://www.remotion.dev/docs/media/support)). One caveat: `@remotion/media` 4.0.539 bundles mediabunny 1.62.0, while `@mediabunny/prores` is at 1.65.0, so check version alignment before relying on it ([npm @mediabunny/prores](https://www.npmjs.com/package/@mediabunny/prores)). A high-bitrate H.264 MP4 avoids that question. Remotion uses NVENC on Windows from 4.0.484 for H.264 and H.265 only ([hardware acceleration](https://www.remotion.dev/docs/hardware-acceleration)). The RTX 2060's Turing NVENC lacks AV1 and 4:2:2, so AV1 delivery and ProRes masters are software encodes ([NVIDIA matrix](https://developer.nvidia.com/video-encode-and-decode-gpu-support-matrix-new)). The existing `--gl=angle --hardware-acceleration=if-possible --video-bitrate=10M` scripts are already correct. As a rough scale, the local figure of about 5 s per dressed EEVEE frame at 960×540 suggests hours, not minutes, for a 1080p reel, so heavy 3D belongs in Blender, not in WebGL compositions limited to `--concurrency=1` ([Remotion maps](https://www.remotion.dev/docs/maps)).

For the R3F scenes, the compatible stack is `postprocessing` 6.39.5 plus `@react-three/postprocessing` 3.2.2. Note that the former's peer range `<0.187.0` caps any three upgrade ([npm postprocessing](https://www.npmjs.com/package/postprocessing)). Takram's `@takram/three-atmosphere` 0.19.1 (MIT, beta, drei only optional) would match the Blender sky physically ([npm](https://www.npmjs.com/package/@takram/three-atmosphere)). Avoid temporal effects such as TAA, the temporal upscaling in Takram clouds and progressive path tracing, because Remotion renders each frame independently. For sound, filter Freesound to CC0 (or CC BY 4.0 with credits) and avoid BY-NC and Sampling+ ([Freesound FAQ](https://freesound.org/help/faq/#licenses)). For Welsh voiceover, Bangor University's Piper-based `cy_GB-bu_tts` is CC0, and the package page warns not to feed it to stock piper ([cy_GB-bu_tts](https://hface.pages.dev/techiaith/cy_GB-bu_tts)).

| `mapbox-gl`, deck.gl, `@remotion/lambda` / `cloudrun` / `web-renderer` / `media-parser` / `webcodecs` / `gif` | Proprietary licence; a redundant second WebGL stack; cloud accounts or features this local film does not use |

## Conclusion

The research turns the toolkit question inside out. The risk to this film is not a missing capability but an accumulation of quiet defects: a silent 2 m datum fallback, scripts that exit 0 on failure, an unauthenticated port, unpinned `uvx` resolution, seed drift between Blender versions, and licences that look free but forbid redistribution. Each costs nothing to fix and protects the provenance claim, which is the project's real differentiator. The few genuine capability gaps are vegetation species, error-bounded terrain LOD, and single-photo camera registration. They are best filled with owned output (MTree), small permissive libraries (pydelatin, scikit-image) and custom code on top of the existing stack, not with marketplace packs or foundation models.

Two judgements remain open, and a test render settles each. First, confirm that MTree and the multiple-scattering sky behave on 5.2 under EEVEE. Second, measure a 1080p dressed frame against the 6 GB budget before buying The Grove or Physical Atmosphere². The skyline-to-DSM solver is the highest-leverage piece of new code. It turns scattered Commons photos into calibrated cameras, which is exactly the "photo-matched" promise of the reel, and no off-the-shelf package does it.
